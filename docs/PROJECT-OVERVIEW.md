## Ustoz
Учёт оплат учебного центра / Тестовое задание Ecomdev / 29-10-2026

Рабочий прототип объединяет веб-панель, API, Cloudflare D1 и Telegram-бота. Администратор ведёт учеников, вносит оплаты и видит задолженность за выбранный месяц. Стек: TypeScript, React/Vite, Hono, Cloudflare Workers и grammY.

## Веб-приложение
Интерфейс / Два языка / Две темы

### Ученики

Карточка содержит ID, имя, телефон, группу и месячную сумму. Доступны создание, редактирование, удаление с подтверждением, поиск, фильтр группы и история оплат. Удаление ученика каскадно удаляет его платежи; архивирование пока не реализовано.

### Должники и показатели

Администратор выбирает месяц. Карточки показывают общую сумму тарифов, поступившие оплаты и остаток задолженности. Таблица показывает тариф, оплаченную сумму и долг каждого должника. Из строки можно сразу открыть форму платежа.

### Оплаты и история

Общий реестр показывает последние 500 записей. Для отдельного ученика доступна полная история. Учётная дата определяет месяц платежа, а время создания показывает момент внесения записи. Эти значения отображаются отдельно.

### Ручная запись и симуляция

Для внесения оплаты выбираются ученик, сумма, дата и способ. Ручная запись фиксирует уже полученные деньги. Payme и Click открывают демонстрационное подтверждение с явной пометкой, что деньги не списываются. Успешное подтверждение сохраняет оплату и провайдера; отмена ничего не записывает.

### Языки, темы и мобильный экран

Русский и узбекский латиницей переключаются в интерфейсе. Светлая тема использует синие акценты, тёплая - зелёные на кремовом фоне. Выбор сохраняется в браузере. На телефоне таблица учеников заменяется карточками, формы адаптированы к узкому экрану.

### Демонстрационный режим

Параметр ?preview=1 включает отдельно помеченные вымышленные данные. Изменения действуют до перезагрузки страницы, не отправляются в рабочую базу и не становятся реальными платежами. Обычный режим использует API и требует входа.

Текущие правила: только целые UZS; даты в интерфейсе DD-MM-YYYY; время HH:mm:ss по Asia/Tashkent. API сохраняет даты в ISO-формате.

## Telegram-бот
Команды задания и дополнительные кнопочные сценарии

| Команда | Результат |
| --- | --- |
| /debt | Должники текущего месяца. |
| /pay 1 250000 | Запись 250 000 UZS для ученика с ID 1. |
| /lang ru или /lang uz | Выбор языка, сохранённый в D1. |
| /help, /start | Справка и меню управления. |

### Все ученики и должники

Меню содержит отдельные разделы «Должники» и «Все ученики». Общий список показывает тариф, оплаченные суммы, долг либо переплату за текущий месяц. Можно выбрать ученика без долга и внести дополнительную оплату. Списки разбиты на страницы по 8 человек.

### Внесение оплаты кнопками

1. Выбрать ученика. 2. Ввести положительную целую сумму. 3. Выбрать обычную запись либо Payme/Click. 4. Подтвердить. Бот сохраняет состояние незавершённого ввода. Возврат в меню отменяет операцию.

### Payme и Click в Telegram

Для обоих способов есть отдельный экран симуляции и отдельная кнопка подтверждения. До подтверждения в базе нет записи. Устаревшая кнопка ручного подтверждения не должна принимать симуляцию. После сохранения чек содержит способ, отметку симуляции и дату/время. Повторная доставка подтверждения не создаёт дубликат.

### Доступ и время

Требуются токен отдельного бота, список разрешённых ID и секрет webhook. Команды учёта разрешены только указанным пользователям в личном чате. Для команды /pay дата берётся из времени исходного сообщения в Asia/Tashkent, поэтому поздняя повторная доставка не меняет учётный день.

### Самостоятельная настройка

Создать бота через @BotFather /newbot. Задать TELEGRAM_BOT_TOKEN, TELEGRAM_ALLOWED_IDS и TELEGRAM_WEBHOOK_SECRET в Worker. Для скрипта настройки экспортировать токен и секрет в окружение текущего терминала: .dev.vars он автоматически не читает.

```sh
APP_URL=https://YOUR_APP_DOMAIN node scripts/configure-bot.mjs
```

Без Telegram-настроек веб-панель и API продолжают работать. Существовавшие ранее боты не используются этим проектом.

## API и расчёт долга
Часть 1 / Контракт / Точность учёта

| Метод и путь | Назначение |
| --- | --- |
| POST /api/login; GET /api/session | Вход и проверка сессии. POST /api/logout - выход. |
| GET /api/students | Список учеников. |
| POST /api/students | Создание: name, phone, group, monthlyFee. |
| PATCH /api/students/:id | Изменение полей ученика. |
| DELETE /api/students/:id | Удаление ученика и связанных оплат. |
| GET, POST /api/students/:id/payments | История и внесение оплаты. |
| GET /api/payments | Последние 500 оплат. |
| GET /api/debtors?month=YYYY-MM | Только ученики с положительным долгом. |
| GET /api/balances?month=YYYY-MM | Балансы всех учеников для сводки. |

Маршруты учёта также работают без /api, включая требуемый заданием GET /debtors. Пример тела платежа:

```sh
{"amount":"250000","date":"2026-10-29","method":"manual"}
```

### Правила расчёта

Долг = max(текущий месячный тариф - сумма оплат выбранного месяца, 0). Учитываются даты от первого дня месяца включительно до первого дня следующего месяца исключительно. Ученик без оплат должен весь тариф; полностью оплативший и переплативший не включаются в должников.

Пример: тариф 700 000 UZS, платежи 250 000 и 150 000 UZS в октябре дают долг 300 000 UZS за октябрь. Платёж в сентябре на этот расчёт не влияет.

### Валидация и повторные запросы

JSON-суммы - строки целых чисел; .00 допускается для совместимости. Ненулевые дроби отклоняются. Тариф может быть нулём, платёж должен быть положительным; максимум одного значения - 1 000 000 000 UZS. Проверяются календарные даты, месяц, типы полей и существование ученика.

Idempotency-Key сохраняется при повторе той же операции. Повтор возвращает существующий платёж; изменённое содержимое с тем же ключом даёт 409. Ошибки имеют форму {error:{code}}: 400 неверный ввод, 401 нет входа, 403 запрет, 404 ученик не найден, 409 конфликт, 429 лимит входа.

## Архитектура и хранение
TypeScript / Cloudflare Workers / D1

React/Vite → Hono API в Cloudflare Worker → Cloudflare D1. Telegram webhook обращается к общей серверной логике учёта. Worker также раздаёт собранный интерфейс. Домен проекта - отдельный поддомен ustoz.rieltor.store.

| Компонент | Файлы и назначение |
| --- | --- |
| Веб-интерфейс | src/web/App.tsx, forms.tsx, components.tsx, styles.css: страницы, формы, темы. |
| Клиент и локализация | client.ts, model.ts, i18n.ts, demo.ts: API, форматы, RU/UZ, демонстрация. |
| Сервер | src/server/index.ts, service.ts, domain.ts: маршруты, учёт и проверка данных. |
| Авторизация и бот | auth.ts, telegram.ts: сессии, команды и кнопочные сценарии. |
| Инфраструктура | wrangler.jsonc, migrations/, scripts/, .github/workflows/check.yml. |

### Таблицы базы

| Таблица | Содержимое |
| --- | --- |
| students | Имя, телефон, группа, тариф, время создания. |
| payments | Ученик, сумма, дата, метод, уникальный ключ повтора, время создания. |
| telegram_preferences | Сохранённый язык пользователя бота. |
| telegram_flow | Состояние пошаговой оплаты. |
| login_attempts | Учёт попыток входа для ограничения перебора. |

D1 использует SQLite. Суммы хранятся целыми минимальными единицами, хотя внешний ввод ограничен целыми UZS. Внешний ключ связывает платёж с учеником, индекс по ученику и дате ускоряет историю и месячный расчёт. Создание/изменение схемы выполняется SQL-миграциями.

### Базовая защита

Сессии подписаны; HTTPS-cookie имеет HttpOnly, Secure, SameSite=Strict. Проверяется срок сессии и Origin изменяющих запросов, ограничиваются попытки входа. Telegram проверяет секрет webhook и список разрешённых пользователей. Секреты не должны попадать в Git. Общий пароль остаётся ограничением прототипа: персональных ролей пока нет.

## Запуск с нуля
Часть 3 / Локальная разработка / Публикация

Нужны Git, Node.js 22+ (проверено на 24) и npm. Для локального сайта аккаунт Cloudflare не требуется.

```sh
git clone https://github.com/shuhratartweb-blip/ecomdev-payments.git
cd ecomdev-payments
npm ci
cp .env.example .dev.vars
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

В .dev.vars установить свой APP_PASSWORD и сгенерированный SESSION_SECRET (не менее 32 символов). Telegram-поля можно оставить пустыми. Файл исключён из Git.

```sh
npm run db:migrate
npm run db:seed   # необязательно, только новая пустая БД
npm run dev
```

Открыть http://localhost:8787 и войти с локальным APP_PASSWORD. База хранится в .wrangler/state/ и переживает перезапуск. Seed содержит вымышленные данные и платежи текущего месяца Ташкента.

```sh
# Во втором терминале: интерфейс с горячим обновлением
npm run web:dev
# http://localhost:5173, API проксируется на Worker 8787

npm run typecheck
npm test
npm run build
```

### Развёртывание в своём Cloudflare

После создания D1 заменить database_id в wrangler.jsonc. Заменить или удалить routes для собственного домена. Выполнить удалённые миграции, задать секреты, затем публиковать.

```sh
npx wrangler login
npx wrangler d1 create ecomdev-payments
# Теперь заменить database_id и routes в wrangler.jsonc
npx wrangler d1 migrations apply DB --remote
npx wrangler secret put APP_PASSWORD
npx wrangler secret put SESSION_SECRET
# Для бота: TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET,
# TELEGRAM_ALLOWED_IDS через wrangler secret put
npm run deploy
```

Cloudflare-ключ нужен инструменту публикации; в код приложения он не встраивается. Рабочий пароль не публикуется в открытом GitHub.
